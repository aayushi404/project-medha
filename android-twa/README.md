# Medha — Android app (Trusted Web Activity)

The Play Store app is a thin Android shell around https://project-medha.vercel.app,
generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap). Web
deploys reach app users immediately; a new `.aab` is only needed when
`twa-manifest.json` changes (name, icons, colors, version).

- Package: `com.medha.education.medha_app` — shared with the Flutter app in
  `../Project Medha Android IOS Windows App/medha_app`, so that app can later
  replace this one as a normal update (higher `versionCode`, same upload key).
- Source of truth: `twa-manifest.json`. Everything else here is generated;
  `bubblewrap update` overwrites manual edits to `app/`.

## Prerequisites

- JDK **17** (Bubblewrap rejects other versions) — installed at `E:\jdk-17`
- Android SDK at `%LOCALAPPDATA%\Android\Sdk`
- `~/.bubblewrap/config.json` pointing at both

## Create the upload key (once)

```powershell
& 'E:\jdk-17\bin\keytool.exe' -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

Keep `upload-keystore.jks` and its password backed up outside the repo
(`.gitignore` excludes it). Losing it means requesting an upload-key reset
from Play support.

## Build a release

```powershell
.\build-release.ps1
```

Outputs `dist\medha-<version>.aab` (upload to Play) and `dist\medha-<version>.apk`
(`adb install` for testing). Before each new upload, bump `appVersionCode` and
`appVersionName` in `twa-manifest.json`, then run `bubblewrap update --skipVersionUpgrade`.

## Full-screen verification (Digital Asset Links)

Until the site publishes `/.well-known/assetlinks.json` listing this app's
signing certificates, Android opens the app with a browser URL bar on top.
The file needs the SHA-256 of:

1. **Google's app signing key** — Play Console → Test and release → App
   integrity → App signing. This is what users' installs are signed with.
2. **Your upload key** — so APKs you sideload for testing also verify:
   ```powershell
   & 'E:\jdk-17\bin\keytool.exe' -list -v -keystore upload-keystore.jks -alias upload
   ```

The file lives at `shiksha_sathi/public/.well-known/assetlinks.json` and
deploys with the website.
